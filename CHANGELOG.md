# Changelog

## 2026-10-21 — review fixes (app, Textual launcher, build-app.sh)

- App and Textual launcher: root no longer runs the CLI from a folder the user can write to. Before, the elevated remove ran `office-license-removal` from `Contents/MacOS/` or `dist/`, so any process running as the user could replace the binary between the confirmation and the password prompt. Now the front end hashes the CLI (SHA-256) when you confirm. The elevated shell then makes a root-only temp dir (`/usr/bin/mktemp -d /private/tmp/olr.XXXXXX`), copies the CLI into it, and runs the copy with `remove --yes --user <you>` only when the copy's hash matches. On a mismatch it prints `REFUSED: office-license-removal changed since confirmation` and exits 3, and nothing is removed. The temp dir is left in place. App: the hash comes from `/usr/bin/shasum -a 256`; it must be exactly 64 hex digits, or the remove does not start. The path, hash and user are each single-quoted (`quoted form of` semantics). TUI: the hash comes from `hashlib`. The script runs as `sudo /bin/zsh -f -c <script> olr <cli> <user> <hash>`, so the values are positional arguments and never part of the script text. `-f` stops root's zsh from reading the user's `~/.zshenv`. Why: review finding (time-of-check/time-of-use on a root-run binary).
- App: while a scan or remove runs, Quit (menu, ⌘Q, button) and the window close button do nothing. The status line shows `Wait for the current run to finish.` for 3 s and then goes back to the previous status, unless the run has set a new one first. Why: quitting during an elevated remove left the run without a window to report to.
- Textual launcher: the embedded Python now runs with `-I` (isolated mode), so the current folder, `PYTHONPATH` and the user site-packages cannot inject modules. The dependency check and `--self-test` use `-I` too. Ctrl-C while sudo is running (normally at the password prompt) no longer kills the UI: it prints `Cancelled.`, and the status reads `Cancelled at the password prompt; nothing was changed.` with no rescan. Exit 1 from sudo (wrong password three times) shows `Failed (exit 1)`. Ctrl-C at `Press Enter to return…` after a finished run keeps that run's status. When the launcher reopens itself in kitty, it now closes only the Terminal window whose tab has its own tty (`$TTY`), not the front window. If `$TTY` is empty, it closes nothing. Why: review findings (module injection from the cwd, a crash on Ctrl-C, and closing the wrong window).
- `scripts/build-app.sh`: when ad-hoc signing fails 5 times, the script now prints the last `codesign` error, not a generic xattr message.
- Repo: added `.gitignore` (build output, `Archive/`), copied the corrected 2.7.1-local postinstall into `reference/` as the behavioural spec, and rewrote `README.md` under the STE-flavored rules of the `humanize-asd` skill (short active sentences, no semicolons in prose).

## 2026-10-21 — review fixes (CLI)

- Symlink traversal: new `guard::resolve`. Before each per-user or machine-wide delete or rename, the registry open and each `defaults` write, it walks every component from the canonical home (or system root) down to the target's parent, refuses any symlink, canonicalises the parent, re-runs `guard::check` and refuses a final symlink that points outside. Why: `guard::check` was lexical, so a symlinked `~/Library`, `Group Containers` or `UBF8T346G9.Office` let root delete outside the home. Test `remove_refuses_symlinked_group_container` and unit test `resolve_refuses_symlinks_that_leave_base`.
- Permission errors: existence checks in `scan` and `remove` use `symlink_metadata`, and only `NotFound` counts as absent. Any other error prints `FAILED to inspect <path>: <error>` (exit 2) or `[error]  <what>: <path>: <error>` in scan. Why: `is_file()`/`exists()` return false on any error, so an unreadable container was reported as absent and the run exited 0. Test `unreadable_container_is_an_error_not_absent`.
- Keychain: `security` exit 44 is "not found"; any other non-zero exit prints `FAILED keychain <flag> '<value>': exit <code>: <first stderr line>` (exit 2) or an `[error]` scan line. Classification is the pure `keychain_outcome`, with unit tests. Why: every non-zero exit was read as "not found", hiding a locked keychain or a denied session.
- An explicit `--user` that cannot be resolved (invalid name, unknown user, no home) now stops `scan` and `remove` with exit 1 before any change. The three messages lost their "; skipped per-user steps" suffix. Why: a typo in `--user` used to remove the machine-wide licenses and exit 0. Test `unknown_explicit_user_exits_before_any_change`.
- App quit: `pkill -HUP -u <uid>` signals only the target user's apps, then `pgrep -u <uid>` is polled every 250 ms for up to 5 s, and any app still running prints `WARNING: <name> still running`. With no target user, the quit step is skipped. Why: the old `pkill` hit every user's Office apps and did not wait before the license files were deleted.
- `defaults`: a failed `defaults write` prints `FAILED defaults write <path> <key>` (exit 2). `Cleared OfficeActivationEmailAddress` prints only when the delete succeeded; a missing key prints `OfficeActivationEmailAddress not present`. Why: failures were silent or printed as success.
- Perpetual backup: when `com.microsoft.office.licensingV2.Backup` already exists, the license goes to `….Backup.<YYYYmmdd-HHMMSS>` (local time from `/bin/date`). Why: a second run overwrote the first backup. Test `existing_backup_is_not_overwritten`.
- Registry: `delete_flights` uses an immediate transaction. Why: a deferred transaction took the write lock only at the first DELETE, after the node walk.

## 2026-10-21 — app

- New native macOS app `Office License Removal.app` (crate `app/`, binary `OfficeLicenseRemoval`, Rust + objc2/AppKit). It shows the CLI's `scan` output at launch and after every remove, and has `Rescan`, `Remove Licenses…` and `Quit` buttons. Why: the owner wanted a double-click window instead of the Terminal wrapper.
- `Remove Licenses…` asks for confirmation in a critical alert. Cancel is the default button, and the run goes ahead only when the user presses Remove and types `REMOVE`. It then runs the bundled CLI as `remove --yes --user <current user>` through `osascript … with administrator privileges`. The CLI path and user are single-quoted in Rust (`quoted form of` semantics). The shell appends `OLR_EXIT=<code>`, because `do shell script` would otherwise hide the CLI's exit code. Cancelling the password prompt (`-128`) reports that nothing was changed.
- Lab mode: if both `OLR_LAB_HOME` and `OLR_LAB_SYSTEM_ROOT` are set, the app passes them as `--home` / `--system-root`, runs the CLI without elevation, and marks the window title `— LAB MODE`.
- CLI: `scan` now accepts `--home` and `--system-root`, with the same meaning and checks as `remove`, so the app can scan the fixture tree it removes from. The shared checks moved into `check_overrides`. New integration test `scan_with_overrides_reports_fixture`.
- The repo is now a Cargo workspace (`[workspace] members = ["app"]`) with one `Cargo.lock`.
- App UI test harness `--ui-test <dir> [--flow scan|cancel|remove]` (`app/src/uitest.rs`). It drives the real buttons and alert in-process and writes PNG captures, `menu.txt` and a PASS/FAIL `events.log`, with no focus stealing and no Screen Recording permission. `cancel` and `remove` refuse to run outside lab mode. Why: so a reviewer can check the window and the Remove flow without a human.
- App theme: the window is forced to the dark appearance and uses only crimson `#C00027`, gold `#F4BD47`, black and white. It has a crimson 80 pt header band behind the transparent title bar, with a gold bold title and a white status line; the visible window title is hidden, but the title string is still set. The output is white on black with no scroll border. `Rescan` (gold, bold black title) and `Remove Licenses…` (crimson, bold white title) are borderless buttons that paint their own layer fill with 6 pt corners, because `bezelColor` is only painted while the window is key in the active app. They dim to 45% while disabled. `objc2-quartz-core` 0.3, already linked through objc2-app-kit, is now listed in `app/Cargo.toml` only to switch on those CALayer setters. Frames, actions, alert text and flows are unchanged. Why: the owner's palette.
- New `scripts/build-app.sh`. It builds both crates for arm64 and x86_64, joins each pair with `lipo`, writes `Info.plist`, ad-hoc signs and verifies the bundle, and refreshes `dist/office-license-removal` with the same universal CLI.
- `dist/Office License Removal.command` is now a Textual terminal UI in the crimson/gold palette (Python, `~/.venv`). Before, it was a plain zsh `scan` / `read REMOVE` / `sudo remove` script. The UI shows `scan --user <you>` output at launch and after every remove. It has `[R] Rescan`, `[X] Remove Licenses…` and `[Q] Quit`. Remove opens a confirm dialog: the run goes ahead only when you press Remove and the field reads exactly `REMOVE`. Return or Esc cancels. The real remove suspends the UI and runs `sudo <cli> remove --yes --user <you>` in the terminal, so sudo can ask for the password. Lab mode (`OLR_LAB_HOME` + `OLR_LAB_SYSTEM_ROOT`) runs the CLI directly with `--home` / `--system-root`. `--self-test` checks only the dependencies. `--smoke` builds a fixture in `$TMPDIR` and drives cancel and remove headless through `App.run_test`. Why: the owner asked for Textual. The old wrapper is in `Archive/Office License Removal.command.bak.20261021-092308`.
- Review pass (same day): captures of all three harness flows and the TUI smoke test were re-run by the reviewer on fixtures built from a copy of the real registry (230 flight rows); the real elevated/sudo remove paths and the kitty relaunch remain untested by design.

## 2026-10-21 — 0.1.0

- New Rust CLI `office-license-removal` (`scan` / `remove`). It replaces the postinstall script of Microsoft's "Office for Mac License Removal Tool 2.7" and follows the corrected 2.7.1-local script step for step. It removes the perpetual license plist (kept as `.Backup`), the vNext perpetual folder, the Microsoft 365 subscription files and `Licenses` folder, and the 15 Office keychain items. It also clears the "belongs to" prefs, resets the per-app first-run flags, deletes the ECS flight rows in `MicrosoftRegistrationDB.reg`, and restarts cfprefsd.
- Why: two bugs made Microsoft's 2.7 script fail silently.
  - Its flight reset was a no-op. `[ x == y ]` is not valid in zsh, so every registry lookup returned an empty string.
  - Its keychain deletes ran in root's securityd session, where the user's login keychain is locked. This tool runs the deletes in the user's session (`launchctl asuser … sudo -u`) and repeats each one until nothing matches, up to 20 times.
- Registry edits use parameterised SQL in one transaction. A path guard refuses empty paths, `/`, `..` and paths outside the resolved home or system root before any delete. The home folder is canonicalised first, because `defaults` silently ignores a path domain reached through a symlink such as `/var` → `/private/var`.
- Lab mode (`--home` + `--system-root`) runs against a fixture tree without root and skips the app quit, keychain and cfprefsd steps.
- Added `dist/Office License Removal.command`, a double-click zsh wrapper.
- Review pass (same day): a path-guard refusal of the home folder now sets exit code 2 instead of 0, so a management policy notices that per-user data was left in place. `dist/office-license-removal` is a universal (arm64 + x86_64) ad-hoc signed binary built with `lipo`; the Cargo release artefact alone is arm64.
